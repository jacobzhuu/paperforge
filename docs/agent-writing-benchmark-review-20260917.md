# 已完成 A/B/C 写作 benchmark 审阅（2026-09-17）

结论：**保持线上 `legacy`，本轮 `release_eligible=false`。先修正评估覆盖和做小范围、有证据支持的优化，再另立实验重测。** 本次只读取历史产物、导出只读快照并生成审阅材料，没有重新调用模型、修改原始结果、放宽 gate 或更改线上配置。保留 legacy 是维持既定发布基线，不代表 legacy 的论文质量已经合格。

## 1. 数据范围与可复现性

- 一个真实项目：对比学习在小样本图像分类中的应用；73 篇入选文献，44 篇有全文。6 个问题章节、综合、证据附录、3 个框架章节，共 11 节。
- 3 个条件 × 3 轮，顺序 A/B/C、B/C/A、C/A/B；冷缓存。A=`legacy`，B=`dag_serial`，C=`dag_parallel`（width=2）。
- 旧大纲仅在评测副本补充当前生成器的依赖契约；原有章节、证据与篇幅未改变。DAG 为 `s1..s6 → s7 → evidence_ledger → frames`。第一层有 6 个独立节点；框架节点在实现中仍顺序执行。
- 读取了 cold.json、9 份原始最终 Markdown、99 节持久化 PaperIR、879 个事件、282 条 LLM 账本记录和 1485 条项目证据。282 条调用的时间、Token、prompt hash 与数据库逐条一致；282 个 reservation 与账本对应，165 个 span 全部成对结束。无调用错误、无缺失用量、无未定价调用。
- fixture/model config hash 各只有一个；6 个独立章节的 B/C 首次请求 prompt hash 在全部轮次中逐节相同。54 次章节评审输入均重建成功，prompt hash **54/54 匹配**。
- 稿件做了全量结构/来源映射检查和重点段落对读；本报告是已知条件的分析审阅，**不是人工盲审、不是新的模型裁判分数**。未给 organization/evidence/consistency 填造分数。
- 只有一个主题、每条件三次，不能证明跨主题稳定收益或统计意义上的质量非劣。温度采样、输出长度和服务时段仍可影响耗时。轮换顺序降低了固定顺序偏差，但不消除这些因素。

### Organization

三组均沿同一大纲完成 11 节；s1/s3/s4 多次重复解释 InfoNCE、自监督/监督对比及预训练范式，这是共同的大纲职责重叠，不能全部归咎于并行。

A 有更多依托前文的衔接；B/C 的初始独立章节更像自包含单元，随后由同一个整合/润色流程补衔接。没有证据表明 C 全面失去组织性，也没有证据足以认定其质量非劣。机器跨研究综合段落率 A 为 0.702/0.766/0.660，B 为 0.796/0.692/0.706，C 为 0.712/0.760/0.648；方向不一致。这是启发式指标，不是人工 organization 分数。

A2 的重复涉及 s1/s2，C1 涉及 s2/s3；精确重复段落检测与此近重复规则不同，不能用“无逐字重复段落”驳回其报警。B3 的 s2 被语义模型标为 `listed`，其他大部分章节被标为 `synthesized`；该标签仅供盲审定位。

### Evidence support：质量问题与测量问题同时存在

1. **共用证据基础受限。** 写作者反复承认不同骨干、任务协议、零样本/小样本设置不可直接排序，却又写出“总体优于多数元学习基线”等上位结论。例如 C1 s2/P5 同段先称“总体优于……多数元学习基线”，后称缺少统一骨干/协议的严格对照。这应由人工核对论断强度，而不是因为末尾附了一句局限就自动通过。
2. **语义评审看不到全部写作证据。** 评审从 question-evidence links 取池，写作则使用大纲绑定的证据；两者还可能存在池成员差异。评审每节只输入去重证据池前 14 条，每条最多 700 字；各节池规模是 13、13、27、21、21、19。对 s3/s5 尤其不完整。54 次 prompt hash 已重建验证，正文都不足 4000 字，本次主要截断发生在证据侧，而不是正文侧。
3. **已确认一个误归因实例。** B1 s5/P1 引用的证据 `5f3aa3e2-1ca1-4382-a969-0ffb39914f86` 明确写有 CLIP 的 27/16 数据集比较；`5bb65ee7-b73a-4289-a2d1-0b010875fae9` 写有 4 亿图文对。前者在完整评审池中排第 20，因前 14 条限制未被展示；后者甚至不在该节评审池中。两条都属于写作者实际引用的项目证据。原模型把这些列为无证据，因此“51/54 未通过”不能直接解读为 51 节真实幻觉，也不能据此判 C 比 A 更差。
4. **证据 ID 有效不代表来源内容无误。** 九稿 s6 都出现“查询集类别与支持集类别不重叠”的表述，引用的 `6f94f0c4-ed8e-428f-aa1b-a9321a64dd31` 原文确实含相同陈述。此处需领域评审者核查原文/任务设定，属于可能的源证据或提取问题，不能算作 C 独有的无来源改写。
5. **claim verifier 不是全量生效评估。** 九次均 `mode=shadow`、`status=partial`；每稿主检查 60 个候选，候选总数为 95–130，尚有 35–70 未核验，persistent cache hit 均为 0。C2 另有 6 个替代证据检查。shadow 判定没有实际 promote/demote；因此“unsupported strong claim rate=0”等字段不能理解为完成了全稿无幻觉认证。`failed_count` 在这些报告中与 `unverified_count` 相等，不是 35–70 次 HTTP 调用失败。

### Consistency

整合前术语冲突数 A 为 **1/0/0**，B 为 **5/6/5**，C 为 **8/5/6**。冻结上下文增加了首次提议的译名分歧，例如 C1 的 episodic training（情景式/情节式）、adapter（适配器/适配层）。这是 Integration 的输入，不是最终未修复矛盾计数；B 与 C 接近，说明主要变化来自冻结上下文，而非 width=2 本身。

框架章节已绑定正文 snapshot，但 snapshot 新鲜不能证明语义一致。A1 结论把 CLCE 与 VarCon 并提为在少样本基准稳定超越对照，而正文又区分 VarCon 的普通分类证据；B3 s3 的“上一节梳理的方法谱系”与前一节实际是性能比较的职责也值得复核。C3 摘要主要交代覆盖范围、缺少实质发现，结论却给出更强的总体收益断言；这是最终 Integration/Evaluator 应覆盖的质量维度。

本次 6 个章节语义评审只覆盖有 question_id 的 s1..s6；摘要、引言、结论、综合和附录没有经过这一项问题回答评审。`polished_count=8` 只说明执行了 8 次润色流程，当前 trace 没有记录每次候选是否被 sentence/provenance guard 拒绝，不能证明 8 次均改善了最终稿。

## 4. B→C 的关键路径

以下用三次**均值**做可加的成本分解；发布判定仍用原中位数。LLM 行是已记录调用区间的时间并集，并发调用不重复计时；“其余”是写作墙钟减去调用区间并集。

| 墙钟组成（秒） | A 均值 | B 均值 | C 均值 |
|---|---:|---:|---:|
| s1..s6 初写（含内部重写，调用并集） | 167.13 | 165.04 | 88.43 |
| s7 + evidence_ledger 初写 | 62.97 | 61.97 | 61.98 |
| 8 节 coherence 模型调用 | 215.53 | 193.97 | 190.27 |
| 摘要、引言、结论模型调用 | 44.86 | 43.69 | 39.84 |
| 其余写作时间 | 2.30 | 2.66 | 2.03 |
| 写作总时间 | 492.79 | 467.34 | 382.55 |
| 写作后的 Evaluator（另计） | 77.36 | 78.36 | 82.22 |

C 第一层模型服务总时长约 165.82 秒，被重叠为约 88.43 秒；主要收益确实来自独立 Writer 重叠执行。C 的正文整合/润色事件区间平均 **190.85 秒**，约占写作 **49.9%**。`_integrate_body` 的确定性整理到 `polish.started` 仅毫秒级，不能把 190 秒误认为字典合并耗时；长时间在后续 8 次 coherence 调用。

单次事件区间：

| 轮次 | B 正文生成 | C 正文生成 | B 润色 | C 润色 | B 框架+组装 | C 框架+组装 |
|---|---:|---:|---:|---:|---:|---:|
| 1 | 219.82 | 146.84 | 177.69 | 193.19 | 45.14 | 37.08 |
| 2 | 216.91 | 159.41 | 183.54 | 183.90 | 39.86 | 41.91 |
| 3 | 248.38 | 147.38 | 222.49 | 195.46 | 48.13 | 42.43 |

第 1 轮并行节约的一部分被 C 更长的润色抵消；第 2 轮 C 有额外章节重写；第 3 轮 B 的生成/润色都更慢。门槛中位数对应 B1 与 C2，不能用某一对阶段差直接拼出 57.42 秒；表格和每轮数据保留了这一统计区别。

等待与基础设施判断：

- 进程内 LLM gate：282 条记录的 `local_queue_wait_ms` 均为 0（毫秒精度）。
- shared provider slot：每稿全部调用累计仅 **0.030–0.046 秒**。没有它把 width=2 压回串行的证据。
- RPM/TPM：历史记录没有 `rate_limit_wait_ms` 字段，不能把缺字段当测得 0。也没有独立的 provider 侧排队、首 Token 与生成耗时分解，不能声称服务端无排队。
- DAG 槽位排队是预期的宽度限制，不等同于 shared limiter 等待。第一层后四个任务需等前面的槽位；C2 某节点内部重写还制造了长尾。
- SQL、落库、预算预留、事件、解析/组装没有独立完整分段；写作调用并集之外剩余 **1.96–2.93 秒/稿**，是可见的非模型串行空隙总量，不能全归给数据库。与调用重叠的 SQL 不在这项里。没有支持“DB/Redis 是当前主瓶颈”的证据。
- benchmark 直接调用 `write_document`，并未走 ARQ enqueue/worker admission。不能用本结果量化线上队列等待、多租户吞吐或容量收益。
- Evaluator 先做 soft check，claim verifier 内部存在并行，随后 benchmark 逐节串行执行 6 个 semantic reviews。B/C 的 semantic reviews 平均约 32.00/34.99 秒。Evaluator 不在本次写作速度 gate 内，单独优化它不能让 13% 写作提速通过 15% 门槛。

可交互时间线：[timeline.html](../.paperforge/agent-benchmark-20260916/review/timeline.html)，可按 A1–C3 切换，悬停查看每个调用的耗时与 Token。

## 5. 13% 是否已到 width=2 上限

**第一层排程接近上限；整个 writing pipeline 还没有。** 不能把两个层次混为一谈。

将每个节点的已测执行时长视为不可分割任务，穷举 6 个节点在两个槽位上的分配，可得一个“同一批时长、无额外开销”的离线下界。这不是新实验，也不承诺换调度后模型耗时相同。

| C 轮次 | 第一层实测秒 | 最优双槽下界秒 | 仅重排最多可省秒 | 双槽利用率 |
|---|---:|---:|---:|---:|
| 1 | 84.748 | 82.818 | 1.930 | 96.1% |
| 2 | 97.640 | 96.090 | 1.550 | 87.5% |
| 3 | 83.098 | 83.069 | 0.029 | 99.4% |

C2 利用率较低主要是内部重写长尾；在保持节点不可分割及当前恢复契约时，即使最优重排也只能再省 1.55 秒。调换顺序并不是补齐 8.98 秒差距的可靠方案。

反过来，把 B 的已测节点时长冻结，只把第一层改为现有 FIFO width=2，三次写作反事实约为 **366.81、365.80、429.47 秒**，按相同中位口径预计下降 **17.13%**。这说明依赖图本身没有把上限锁死在 13%；实际 C 还受到重写、后续生成长度及响应波动的影响。该反事实不能替换实测 gate。

工程上更大的空间在串行阶段，但需要明确区分风险：

1. **低风险、先做观测补齐：** coherence 记录 accepted/unchanged/rejected 及具体 guard 原因、Token、正文前后 hash。当前不知道 8 次昂贵润色有多少真正被采纳，不应先删掉它或改为无条件跳过。该埋点本身不承诺提速。
2. **可局部实施的成本优化候选：** coherence 返回 `sentence_id + 新文本`，由服务端保留原 citation/evidence/source 绑定，继续检查 ID 顺序和逐句数值；减少模型重复输出不可变字段及重复正文。当前平均每稿 coherence 输入约 6.3–6.6 万 Token、输出 3.2–3.3 万 Token，收益空间明确，但必须经过 provenance 回归和新的模型评测。
3. **受限并行候选：** 正文完成后冻结最终 glossary/findings，宽度 2 生成框架章节，再按大纲顺序提交。本次 C 的 3 个框架调用总和 36.34–41.86 秒；固定时长下双槽 FIFO 可节约约 13.4–20.9 秒，量级足以覆盖当前差距。代码复核更正：框架首轮循环不调用 `register`，其输入已经共享最终正文上下文；会调用 `register` 的是恢复补写路径和正文 polish。因此首轮框架可以在冻结上下文后受限并行，恢复补写仍应串行。此更正不改变上述历史实验数据或 release 结论。
4. **暂不做：** 把 8 节 coherence 直接全量并行。它读取前两节摘要，并在每次完成后更新上下文；需要新的冻结/依赖契约和一致性验证。也不建议为约 2 秒残差重写数据库层、增加跨 Worker 子任务或放松共享限流。

以上均为后续候选，当前未改实现、未启动重测。

## 6. B 相对 A 的来源

原中位数是耗时 -7.14%、Token -5.54%。**有直接证据支持“输入上下文更精简”，但不能把全部降幅因果归给新设计。**

- 六个问题章节的首次输入 Token：A 为 **37931/38012/37852**，B 每次都是 **34987**，稳定少 **2865–3025**（约 7.6–8.0%）。s1 的 A/B prompt hash 相同；从 s2 起 A 加入前两节滚动摘要与累计术语，B 用冻结 glossary 和声明依赖。B/C 六个首次 prompt hash 全部一致，直接证明这部分差异来自上下文设计，而非不同证据或重复缓存命中。
- 总 Token 包括正文、润色、框架和评估。三次均值 A→B 少 **13297 Token**，其中首层输入少约 5775（含 A1 额外重写的输入），coherence 输出少约 **5016**；这些合计远不只是首次 prompt 节省。A1 有一次额外 `write_retry`，B 没有；不能把这一次随机恢复节省外推成必然收益。
- 耗时均值 A→B 少 **25.45 秒**，其中 coherence 调用少约 **21.56 秒**；六节初写模型时长均值只少 **2.09 秒**。A3 coherence 输出达到 **45507 Token**，其他多数在约 3 万上下；输出长度/模型响应波动对速度差贡献很大。
- 每轮 A→B 都更快，但幅度为 5.87%、7.63%、2.33%；并非稳定的 7.1%。B 的最终正文长度也不是按固定字数严格锁定（详见 metrics.json）。
- 计时边界一致、缓存均冷、模型身份一致、账本已对齐，没有发现把某组 evaluator 错算进写作的计量错误。可是三次样本不足以排除服务时段、采样和重写概率的混杂。准确表述应是：**上下文输入节省已证实；总耗时/总 Token 改善是本样本观察值，尚不是纯粹的上下文设计因果效应。**
