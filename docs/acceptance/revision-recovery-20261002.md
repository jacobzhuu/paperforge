## 行为

- 候选新增可空 `recovery_json`，保存修复计划、依赖章节、输入/输出指纹、所属任务及逐操作状态。迁移 `0040_revision_recovery` 兼容仍在运行的旧 worker。
- 章节正文与完成标记在同一事务提交；恢复跳过已经提交且内容匹配的章节，继续尚未执行部分。明确失败最多两次尝试，第二次必须由用户继续任务触发。
- 保存修复目标与来源指纹，避免父章节完成后遗漏待执行的依赖章节；研究范围、写作材料或已保存候选内容变化会阻止旧计划继续。

- 已开始但无法确认持久化结果的操作保守阻止重放；旧任务只有“已尝试”记录时同样阻止自动重试。不会把未知状态当作完成，不会自动重新购买结果不明的调用。
- 后台任务使用累计运行时长，排队与暂停间隔不计入新执行的计时。调用次数及 token 预留继续累计，耗尽预算时 API 在创建新任务之前拒绝恢复。运行时长随模型预留、心跳及收尾持久化；异常硬退出仍以最后持久化计时为准。
- 修订列表返回 `can_resume`、`resume_block_code`、`resume_block_reason` 和 `recovery_message`；现有卡片显示原因，隐藏无效恢复按钮，排队任务不再显示暂停。
