# 27 稿写作实验速度归因

分析对象：`.paperforge/agent-upgrade-20260918/writing-topic-{1,2,3}/cold.json`，
以及隔离评估库对应 27 个任务的事件。未追加模型调用，未改生产代码或配置。
逐运行派生指标保存于私有 `speed-analysis.json`；原始结果保持不变。

## 核心结论

并行机制实际工作，但 B/C 只改变摘要、引言、结论的框架生成并发宽度 1→2。
B/C 的正文模式均为 dag_parallel，正文宽度均为 2；本实验不是整个写作流程从串行改为并行，
也没有调用 LangGraph 语义修复子图或比较混合检索。

| 主题 | B 框架阶段中位秒数 | C 框架阶段中位秒数 | B 框架占全稿耗时的比例中位数 | B 全稿中位秒数 | C 全稿中位秒数 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 1 | 48.64 | 28.81 | 7.15% | 698.83 | 723.56 |
| 2 | 38.42 | 20.67 | 8.18% | 469.85 | 518.34 |
| 3 | 49.20 | 39.74 | 9.47% | 519.61 | 510.01 |

事件时间线验证 B 框架峰值并发为 1，C 为 2。阶段已变快；其份额只有约 7%–10%，
在其余工作保持相同时，即使将框架阶段耗时降到零，也不足以达到全稿缩短 15% 的门槛。
因此本轮优化范围与验收目标不匹配。保留原门槛和未通过结论，不事后放宽标准。
各列分别取中位数，不能将中位数差直接相加作为完整耗时分解。

## 未被优化的大部分工作

`document.py::_polish_all` 使用逐节 `for` + `await coherence_pass`，每节更新上下文并落库。
B 的润色实际墙钟中位数分别为 385.52、190.94、202.42 秒；
C 分别为 424.62、205.21、211.53 秒。逐运行占比的中位数约 39%–59%。
不能不检查上下文依赖就将它直接替换成 gather。

正文依赖图：主题 1 每次的 ready 波次大小为 [6,16,1,1]；主题 2 为八个单节点波次，
主题 3 为七个单节点波次。后两主题没有可同时执行的正文节点。
`section_graph` 对未声明 independent/depends_on 的章节默认依赖前一正文节；
这是保守依赖策略，不是并发执行器失效，也不表示这些章节在语义上已经证明可并行。

## 排除的主要嫌疑

写作阶段 27 次运行的累计本地 semaphore 等待均为 0 ms（计时精度内）；
单稿共享 provider 槽位等待总和最大仅 0.544 秒，未记录 rate_limit_wait_ms 等待。
框架落库耗时总和的组内中位数约 0.37–0.69 秒。
B/C 写作耗时扣除实际 HTTP 尝试区间并集后，剩余时间的组内中位数约 4.1–7.4 秒。
因此现有记录不支持本地排队、Redis 配额或数据库提交是主要瓶颈。
HTTP 时间包含网络、代理、供应商内部排队及生成，当前记录不能进一步区分这些部分；
未记录限流等待也不能证明供应商内部没有限流。

## 波动和额外调用

框架开始之前的耗时中位数 B→C：主题 1 为 646.69→689.24 秒，
主题 2 为 430.64→493.67 秒，主题 3 为 469.47→483.64 秒。
框架宽度的执行差异在此之后才发生，因此不能把这些前置耗时差归因为框架并行本身。
不同生成结果、输出长度、模型服务速度和实验期间资源竞争都可能影响这一段，当前证据不能单独定因。

主题 3 的 B 框架调用数为 [3,3,3]，C 为 [3,4,4]；后两次额外调用削弱了阶段加速。
写作调用账本未记录调用错误，额外工作不能简单解释为网络报错重试。

每主题每组仅 3 次重复，中位数易受波动影响。例如主题 1 按中位数 C 比 B 慢 3.54%，
按均值却是 B 700.44 秒、C 692.57 秒，方向相反。
数据支持“本轮未达到速度门槛”，不支持“并行必然使全稿变慢”的因果结论。

## 后续优先级

1. 先针对润色的大耗时做设计：识别无需改写的章节、保留质量核查，评估冻结输入后的依赖分层和受限并发。
2. 审查开发主题正文的真实依赖，显式标记可独立执行的章节；不靠盲目提高并发数字突破依赖。
3. 将框架阶段测试固定在同一正文快照，验证局部加速；完整写作实验独立验证端到端收益，增加重复并控制干扰。
4. 保留模型请求区间、输出长度、重试原因及正文/润色/框架分段耗时，避免仅看总 Token 或总耗时。

这些是下一轮验证方向，不是已经实现或已证明的收益。第三主题保持保留测试用途，不用于调优。
